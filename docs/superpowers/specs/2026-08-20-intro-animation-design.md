# 인트로(스플래시) 애니메이션 설계 문서

작성일: 2026-08-20
상태: 사용자 스펙 확정, 구현 계획 대기

## 1. 목적과 배경

- 서비스: 관계온도 — 카카오톡 대화 기반 관계 분석 서비스
- 목적: 첫 진입 시 사용자가 별도의 설명 없이 `인물 등록 → 카카오톡 대화 업로드 → 관계 분석 → AI 상담 → 실제 대화로 연결`되는 서비스 흐름을 직관적으로 이해하도록 한다.
- 핵심 메시지: **"대화를 분석하고, 관계를 이해하고, 실제 행동까지 도와주는 서비스"**

## 2. 노출 조건

- `/login` 진입 전에 인트로 애니메이션 노출
- 비로그인 사용자의 최초 진입 시 1회만 재생 (`sessionStorage`의 `introPlayed` 키로 기록)
- 로그인 상태라면 인트로 없이 바로 `/dashboard` 이동
- 같은 브라우저 세션에서 다시 `/login`에 접근해도 재생하지 않음
- 인트로는 사용자에게 스킵 불가. 단, 개발·시연 편의를 위한 숨은 스킵 단축키(`Esc` 등) 1개를 둔다 — UI에 노출하지 않음
- 인트로 종료 후 자연스럽게 실제 `/login` 화면으로 전환

라우팅 분기:

- 로그인 사용자 → `/dashboard`
- 비로그인 + `introPlayed === "true"` → `/login`
- 비로그인 + 최초 방문 → `/intro` → `/login`

## 3. 연출 시나리오 (총 약 13초)

애니메이션 전체가 실제 서비스를 조작하는 데모처럼 보이도록 구성한다.

### Scene 1 — 서비스 시작 (0.0~1.0초)

- 별이 천천히 움직이는 우주 배경 (기존 Starfield)
- 화면 아래에서 Astronaut 캐릭터가 부드럽게 위로 등장
- `/login` 화면(축약 버전)이 함께 표시
- Astronaut 또는 작은 커서가 로그인 버튼으로 이동 후 클릭 애니메이션
- 전환: 버튼 클릭 시 화면이 살짝 확대되면서 `/dashboard` 데모 화면으로 전환

### Scene 2 — 새 인물 등록 (1.0~2.0초)

- `/dashboard` 데모 화면 표시
- Astronaut가 `+ 새 인물 등록` 버튼 방향으로 이동, 근처에서 살짝 멈춘 뒤 클릭
- 등록 화면이 카드 형태로 확대되며 등장 (Card Zoom Transition)

### Scene 3 — 관계 정보 입력 (2.0~3.2초)

- 이름 입력: `홍 → 홍길 → 홍길동` 타이핑 효과 (타이핑 효과 사용처 1/3)
- 관계 선택: `친구 / 가족 / 연인 / 기타` 버튼 중 커서가 **연인** 클릭, 선택 버튼에 glow
- 커서가 **다음** 버튼 클릭

### Scene 4 — 카카오톡 대화 업로드 (3.2~4.5초)

- 카카오톡 화면을 서비스 디자인에 맞춘 간략화된 데모 UI로 표현 (실제 카카오톡 UI 복제 금지)
- 흐름: `채팅방 → 메뉴 → 대화 내보내기` → `.txt` 파일 아이콘 생성
- 커서가 파일을 업로드 영역으로 Drag & Drop → `홍길동_대화.txt ✓` 체크 표시
- 커서가 **다음** 버튼 클릭

### Scene 5 — 체크인 (4.5~5.3초)

- Q1 `최근 상대와 대화가 즐거웠나요?` → `2점` 클릭
- Q2 `최근 관계에 만족하고 있나요?` → `3점` 클릭
- **분석 시작** 버튼 클릭

### Scene 6 — AI 분석 (5.3~6.5초)

- 화면 중앙에 Astronaut, 주변에 별/데이터 파티클
- 텍스트 순차 변경: `대화 패턴을 확인하고 있어요` → `감정 표현을 분석하고 있어요` → `두 사람의 관계를 분석했어요 ✓`
- Progress/원형 로딩 완료 후 **리포트 보기** 버튼 클릭

### Scene 7 — 관계 리포트 (6.5~7.4초)

- `/report` 데모 화면 빠르게 등장, 대표 지표 노출:
  - 관계 온도 `72°`
  - 먼저 연락한 비율 `7 : 3`
  - 애정 표현 `최근에도 지속`
  - 자주 등장한 장소 `한강`
- 하단 **AI와 상담하기** 버튼 강조 → 클릭

### Scene 8 — AI 상담 (7.4~9.5초)

- `/chat` 데모 화면
- 사용자 메시지 타이핑 (타이핑 효과 사용처 2/3): `요즘 권태기인 것 같아.. 대화 분석 결과는 어때?` → 전송
- AI thinking 애니메이션 후 답변 등장 (타이핑 없이 문단/Bubble 단위 fade-in):

  > 연인과의 관계가 예전 같지 않아 많이 속상하셨겠어요.
  >
  > 최근 대화를 분석해보면 7월 20일, 26일, 28일에도 '사랑해', '좋아해' 같은 애정 표현이 이어졌고, 상대방이 먼저 연락한 비율도 약 **70%**로 높아요.
  >
  > 또 두 분이 **한강 이야기를 자주 나누고 있어요.** 먼저 한강 데이트를 제안해 편하게 시간을 보내며 솔직한 이야기를 나눠보는 건 어떨까요?

- 마지막 문장의 **`한강 데이트를 제안해보는 건 어떨까요?`** 부분 강조

### Scene 9 — 실제 행동으로 연결 (9.5~11.5초)

- AI 채팅 화면이 옆으로 밀리며 카카오톡(간략화 데모) 대화 화면 등장
- 홍길동에게 메시지 타이핑 (타이핑 효과 사용처 3/3):
  `나 최근에.. 우리 관계가 조금 권태기인 것 같아. 같이 한강 가서 이야기해볼까?` → 전송
- typing indicator `···` 후 상대방 답장:
  `그랬구나.. 몰라줘서 미안해. 한강 가서 같이 맛있는 것도 먹고 이야기해보자 :)`

### Scene 10 — 로고 리빌 & 로그인 전환 (11.5~13.0초)

레퍼런스: Fauna Robotics 로고 리빌 (https://mobbin.com/sites/sections/f45b4c3d-e5bc-4951-8962-e6a61cc4afce)
— 로고 글자가 추상 글리프 상태로 시작해 순차적으로 실제 글자로 풀리며 정착하는 디코드 연출.

- 카카오톡 화면이 천천히 흐려짐
- 화면 중앙에 우주 오브젝트 4개가 떠오름: 우주선 · 우주인(기존 Astronaut 축소) · 행성 · 달(기존 Moon 축소) — 각자 둥둥 떠다니는 float 상태
- 오브젝트들이 왼쪽부터 한 글자씩 순서대로 플립/모핑되며 **"관 · 계 · 온 · 도"** 글자로 정착 (Fauna의 글리프→글자 디코드 리듬)
- 글자가 완성되면 LogoMark가 옆에 붙고, 아래로 태그라인 페이드인:

  **"당신의 대화 속에 관계를 이해할 힌트가 있어요."**

- 약 0.6초 유지 후 전체 화면 opacity 전환으로 실제 `/login` 화면 등장, 인트로 종료

## 4. 비주얼 스타일

- 전체 컨셉: 차분한 우주 감성 + 따뜻한 관계 분석. SF/기술 느낌보다 감정과 관계를 다루는 따뜻한 분위기
- 배경: 기존 `Starfield` 활용. 어두운 navy/deep purple, 별은 천천히 이동, 화면 전환 시 별 위치 유지 — 하나의 공간에서 서비스 기능을 여행하는 느낌
- Astronaut: 기존 컴포넌트를 가이드 역할로 사용. 장식이 아니라 사용자 행동을 대신 수행 (로그인 이동, 버튼 클릭, 분석 관찰, 채팅 대기). 이동은 `translate3d()`, `scale()`, `rotate()` 위주
- UI 표현: 실제 페이지 전체 전환 대신 중요한 UI만 확대하는 Spotlight 방식. 나머지 영역은 약간 어둡게
- 색상: 기존 `theme.css` 변수 재사용. 관계 데이터 강조(`사랑해`, `좋아해`, `70%`, `한강`)는 Pink/Lavender accent로 한 단계 밝게
- 화면 전환: fade 반복 대신 Card Zoom Transition + Shared Element Transition(Astronaut는 새로 생성되지 않고 이전 위치에서 다음 위치로 이동)

## 4.5 모션 레퍼런스 (CTRL 월렛 랜딩 섹션)

사용자가 지정한 레퍼런스: https://mobbin.com/sites/sections/f50cd5ce-6131-43a1-9866-7a7e57583fbd
(CTRL 크립토 월렛 랜딩 페이지의 8.35초 자동 데모 섹션, 1920x1200 / 60fps)

레퍼런스에서 차용할 핵심 기법:

1. **중앙 고정 프레임 + 내부만 전환**: 디바이스 프레임(우리는 서비스 데모 창)은 화면에 고정된 채 내부 화면만 바뀐다. 프레임 자체가 Shared Element 역할
2. **데모 커서 블롭**: 반투명 브랜드 컬러 원형 블롭이 커서 역할. 이동 후 클릭 시 살짝 수축(scale down)했다가 복귀. 우리는 lavender/pink 계열 블롭 + Astronaut 조합
3. **블러+줌 화면 전환**: 내부 화면 전환 시 `filter: blur()` + 미세한 `scale()`을 걸어 속도감 있는 모션 블러 연출 (CTRL의 전환 프레임에서 확인된 기법)
4. **단계 아카이브 스택**: 지나간 단계의 설명 카드가 화면 왼쪽에 슬림한 배지 바(카드가 접힌 형태)로 순서대로 쌓인다. `Simple → Convenient → Multichain`처럼, 우리는 `등록 → 업로드 → 체크인 → 분석 → 리포트 → 상담` 진행감을 표현. 13초 여정에서 "지금 어디까지 왔는지"가 항상 보임
5. **양옆 보조 카드**: 현재 단계를 설명하는 카드가 좌우에 등장했다 교체됨. 우리 인트로에선 좌측 스택 + 우측 현재 단계 설명 1장으로 단순화
6. **리스트 stagger 등장**: 리포트 지표 같은 목록형 콘텐츠는 항목이 순차적으로 떠오르며 등장

이징 특성: 전반적으로 빠른 ease-out(감속) 곡선, 클릭 직후 전환은 짧고 경쾌하게(0.3~0.5초), 카드 등장은 부드럽게(0.5~0.7초). 장면당 포커스는 1개 유지.

## 5. 애니메이션 원칙

- `transform`, `opacity`, `filter` 중심으로 구현
- `top/left/width/height/margin`을 프레임마다 변경하는 애니메이션 금지
- 이동 요소에는 상황에 따라 `will-change: transform, opacity` 사용

## 6. 타이핑 효과

전체 길이 관리를 위해 3곳만 사용:

1. `홍길동` (Scene 3)
2. `요즘 권태기인 것 같아..` (Scene 8)
3. 마지막 카카오톡 메시지 (Scene 9)

AI 답변은 타이핑하지 않고 문단/Bubble 단위 fade-in.

## 7. 접근성 및 예외 처리

- `prefers-reduced-motion: reduce`: 긴 애니메이션을 재생하지 않고 `인트로 Logo → 서비스 한 줄 설명 → /login`의 약 0.5~1초 정적 전환만 제공
- 인트로는 실제 API 요청에 의존하지 않고 미리 정의된 Demo Data로 동작
- 만약 API 로딩 의존 구조가 되면: 분석 완료 시점까지 데이터 미준비 시 `대화를 분석하고 있어요` 마지막 프레임을 유지 후 완료 시 다음 Scene 이동. 빈 화면 전환 금지

## 8. 시연 환경

- 주 시연 환경: 데스크톱 (해커톤 심사·데모 기준)
- 모바일: 13초 풀 인트로 대신 reduced-motion과 동일한 짧은 정적 전환 제공

## 8.5 실제 UI 재사용 원칙 (2026-08-20 사용자 피드백 반영)

인트로의 데모 화면은 임의 목업이 아니라 **실제 서비스 화면을 그대로 재생**한다.

- 각 장면은 실제 페이지(AppLayout, DashboardPage, NewPersonModal, ReportPage, ChatPage)의
  마크업과 CSS 클래스를 재사용한다. 실제 Gauge·RadarChart 컴포넌트도 데모 데이터로 그대로 렌더링
- 1240x760 가상 화면을 0.68 배율로 축소하는 스케일러(`.intro-app`)로 실제 비율을 유지
- 체크인은 실제 UI대로 1~7 슬라이더(파일 업로드·스텝퍼 등도 실제 모달 3단계 구조)
- 카카오톡 장면(Scene 9)은 간략화 대신 **실제 카카오톡 채팅방 스킨**(블루그레이 배경, 노란
  말풍선, 상단바, 입력바)으로 재현한다 — 3장의 "간략화" 문구보다 이 원칙이 우선한다

## 9. 구현 아키텍처 (요약)

- `/intro` 라우트에 `IntroPage` 컴포넌트 추가. `App.jsx`에서 라우팅 분기 처리
- 장면 오케스트레이션: JS 상태 머신(현재 scene index + 타이머) 방식. 각 Scene은 독립 컴포넌트로 분리하고 장면 내부 모션은 CSS 키프레임으로 구현 — 타이밍 튜닝, 스킵, 로딩 홀드가 쉬움
- 데모 UI(미니 대시보드·업로드·리포트·채팅·카톡)는 인트로 전용 경량 목업 컴포넌트로 제작하되 실제 페이지의 CSS 변수·스타일 언어를 재사용
- 상태 저장: `sessionStorage.setItem("introPlayed", "true")` — 재생 시작 시점이 아니라 종료(또는 스킵) 시점에 기록

## 10. 완료 기준

- 비로그인 사용자가 최초 진입하면 인트로가 자동 실행된다
- 전체 애니메이션은 약 13초 내외로 완료된다
- 사용자가 직접 클릭하지 않아도 모든 인터랙션이 자동 진행된다
- Astronaut와 Cursor가 실제 사용자의 행동을 대신 수행한다
- `인물 등록 → 대화 업로드 → 분석 → AI 상담 → 실제 행동` 흐름이 명확히 전달된다
- `/dashboard`, `/report`, `/chat` 등 실제 서비스 UI 스타일과 일관성을 유지한다
- 인트로 종료 후 실제 `/login` 화면으로 자연스럽게 연결된다
- 같은 세션에서는 인트로가 다시 실행되지 않는다
- 로그인된 사용자는 인트로를 거치지 않고 `/dashboard`로 이동한다
- `prefers-reduced-motion`에서는 긴 애니메이션을 생략한다
- 모든 주요 애니메이션은 `transform`, `opacity` 위주로 구현한다
